# Table clearance implementation plan

**Goal:** Keep every player card inside the table container with consistent visible edge clearance.
**Summary:** Give the lowest cards the same comfortable inset as cards at the sides, instead of letting their bottoms touch the border.
**Architecture:** Bound the shared orbit using available workspace dimensions, card dimensions and a common clearance; avoid seat-specific nudges.
**Tech stack:** CSS responsive layout, existing React table, real-browser geometry tests.
**Non-goals:** Seat identity/orientation changes (plan 01), card redesign, table ambience changes.

## Evidence and approach
Screenshot IMG_0141 shows seat 1 meeting the container bottom. `app.css:3170-3192` combines 14px workspace padding, overflow:hidden, an orbit cap and a seat-anchor top offset of +22px. The rotation alone is not a proof that clipping is fixed.

1. After plan 01, reproduce at the screenshot-sized iPad layout, measure the actual CSS viewport/DPR, fullscreen safe areas, workspace inner rectangle and all ten card bounds. Record the failing minimum bottom gap.
2. Inspect desktop, short-landscape, tablet and phone table-size/radius/anchor rules; derive the orbit from both axes and reserve space for card height/width and visible card actions. Use the existing common gutter for the target inset and make bottom clearance match the horizontal minimum within a small measured tolerance.
3. Remove the cause of clipping rather than masking it with overflow or shifting only seat 1. Keep the main table visually balanced and controls reachable.
4. Assert all card rectangles stay inset, left/right symmetry remains, and action rows do not overlap or leave the viewport. Compare screenshots in role giveaway and live play with timer panel expanded/collapsed.

**Files:** `apps/web/src/styles/app.css`; `GameTable.tsx` only if a small shared layout variable is needed; `.AI/ipad-layout/` geometry proof.
**Verification:** `npm run test -w @mafia/web -- GameTable.test.tsx GameScreen.test.tsx`; responsive browser matrix.
**Risk:** Fixing a tall iPad can regress short landscape or narrow phone layouts. Verify breakpoints, not just one screenshot.

## Shared boundaries and verification
No commits, pushes, deployment, dependency additions, backend/auth changes, or development database mutations. Preserve the dirty working tree, current fire/lighting work, secret-role handling and canonical game state. Use isolated API fixtures, never the signed-in club, for visual interaction tests. After approval, add a failing focused regression before implementation; run focused browser/component checks while iterating, then `npm run check:local` (the disposable-database route to root `npm run check`) for the completed plan set. Keep artifacts under `.AI/ipad-layout/`. Require actual iPad visual acceptance; emulated WebKit is not hardware proof.
