# Game title placement implementation plan

**Goal:** Keep the game title and stage eyebrow fully inside the header, clear of the table border and exit control.
**Summary:** Align the title with the top controls instead of allowing it to cross the table container edge.
**Architecture:** Make the header's text metrics and reserved height agree across normal/fullscreen responsive layouts.
**Tech stack:** CSS, React headers, Playwright.
**Non-goals:** Moving role navigation or phase counts (plans 04/05), changing title text, broad typography redesign.

## Evidence and approach
`SetupWizard.tsx:465-469` owns role-giveaway title/eyebrow. `app.css:3056-3089` reserves 46px while the first child contains both eyebrow and h1; fullscreen adds 88px left clearance. Other breakpoint-specific header rules also exist. Screenshot shows the h1 crossing the workspace top boundary.

1. Record header, title, eyebrow, exit-button and workspace bounds in the screenshot mode; distinguish text overflow from incorrect content-top positioning.
2. Fit text line-height/margins and header height to one responsive slot. Keep title readable, safely separated from the fullscreen X and toolbar, with no overlap into the workspace.
3. Test role giveaway and ordinary live-game headings, long/localized stage labels, fullscreen/windowed, portrait/landscape and phone.

**Files:** `apps/web/src/styles/app.css`; `SetupWizard.tsx`/`GameScreen.tsx` only if an explicit title wrapper is required; related `SetupWizard.test.tsx`, `GameScreen.test.tsx` and browser geometry tests.
**Acceptance:** Title and eyebrow bounds are inside the header, title bottom above table top, no collision with exit/toolbar; stage text remains accessible.
**Risk:** Existing absolute/fixed positioning can make a margin-only patch conceal rather than fix the conflict.

## Shared boundaries and verification
No commits, pushes, deployment, dependency additions, backend/auth changes, or development database mutations. Preserve the dirty working tree, current fire/lighting work, secret-role handling and canonical game state. Use isolated API fixtures, never the signed-in club, for visual interaction tests. After approval, add a failing focused regression before implementation; run focused browser/component checks while iterating, then `npm run check:local` (the disposable-database route to root `npm run check`) for the completed plan set. Keep artifacts under `.AI/ipad-layout/`. Require actual iPad visual acceptance; emulated WebKit is not hardware proof.
