# Role-draw back action placement implementation plan

**Goal:** Make the existing return-to-player-selection action discoverable and unobscured.
**Summary:** Move “Back to player selection” into the Game menu, rather than leaving it behind the icon row.
**Architecture:** The workspace owns the menu; SetupWizard owns the existing return handler. Introduce only the small typed hand-off needed to invoke that handler from the active role-draw menu, with stage/unmount cleanup.
**Tech stack:** React/TypeScript, existing drawer/focus patterns, Vitest, Playwright.
**Non-goals:** New-game/reset behavior, duplicating return logic, exposing this as a Dev-only tool, discarding role draws.

## Evidence and approach
`SetupWizard.tsx:454-459` returns to player selection while retaining setup and restoring heading focus. Its visible button is at :470-473. `App.tsx:2298-2352` owns the Game/manage drawer. Existing `SetupWizard.test.tsx:191-243` explicitly verifies selection and partial-role-progress preservation.

1. Add a workspace regression: during role giveaway, open Game, activate the back action, land in seat selection with the same host/players/draw progress; menu closes and destination focus is correct.
2. Connect the existing handler to the Game menu only while applicable. Do not reuse Start new game, resetLocalState or clearGameState. Remove the overlapping text button from the header.
3. Preserve/rehost the existing return/re-entry test coverage, keyboard accessible naming, persistence publication and private-role hiding. Remove stale registered action on stage change/unmount.
4. Verify the toolbar contains no obscured stray button and the action is absent outside the applicable stage.

**Files:** `apps/web/src/App.tsx`, `App.test.tsx`, `features/setup/SetupWizard.tsx`, `SetupWizard.test.tsx`, `styles/app.css`, i18n message files only as needed.
**Risk:** An out-of-date callback could mutate an old setup instance; verify switching/resetting sessions and stage changes.

## Shared boundaries and verification
No commits, pushes, deployment, dependency additions, backend/auth changes, or development database mutations. Preserve the dirty working tree, current fire/lighting work, secret-role handling and canonical game state. Use isolated API fixtures, never the signed-in club, for visual interaction tests. After approval, add a failing focused regression before implementation; run focused browser/component checks while iterating, then `npm run check:local` (the disposable-database route to root `npm run check`) for the completed plan set.
