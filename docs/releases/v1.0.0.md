# Mafia Dashboard v1.0.0 release checklist

## Release status

**Status: follow [issue #23](https://github.com/zemskovmm/mafia-dashboard/issues/23).** An open issue means qualification is pending; closure with the required evidence means the v1.0.0 release qualified. The deployed application's `/health/version` value is the configured `major.minor.APP_BUILD_INDEX`, which need not literally be `1.0.0`. Qualification requires the clean commit exposed by `/health/version` to match the local `RELEASE_COMMIT`, every mandatory gate to pass, and the remote commit to be verified.

## Prerequisites and blockers

- [Issue #48](https://github.com/zemskovmm/mafia-dashboard/issues/48), the completion-persistence blocker, must remain closed and its fix must be present in the candidate.
- PostgreSQL 17, Docker with Compose v2, Chrome, WebKit, network access, and the repository's supported Node/npm versions must be available.
- `APP_URL`, `RELEASE_COMMIT`, `APP_BUILD_INDEX`, `SESSION_AUTH_COOKIE`, `SESSION_CLUB_ID`, `SESSION_VERIFY_ALLOW_REMOTE=1`, and `SESSION_VERIFY_EXPECTED_ORIGIN` must identify one isolated authenticated test club on the deployed candidate. Set `APP_BUILD_INDEX` explicitly to the published image's Deploy Azure workflow run number (or the explicit build arg for a self-hosted candidate). It cannot be inferred from a digest or defaulted to local `0` for remote qualification.
- The connected Google account must have YouTube Music access, at least one non-empty playlist, and the selected club must have at least ten saved players.
- No open P0 target-milestone defect may be waived through documentation.

## Release gate matrix

Run `npm run verify:release` from the exact clean candidate. It compares the deployed version against the root `package.json` version’s major/minor plus the explicit `APP_BUILD_INDEX`, and the deployed commit against the exact candidate SHA, before invoking every command in this fixed order and stops on the first failure. The root package patch is replaced by the build index; workspace package versions remain independent.

| Order | Command                       | Required evidence                                                                                                           | Status source   |
| ----- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------- |
| 1     | `npm run check`               | formatting, lint, typecheck, contracts, tests, and builds                                                                   | release summary |
| 2     | `npm run verify:compose`      | production image/configuration, migration failure, real active-session restart, durable readback, repeat migration, cleanup | release summary |
| 3     | `npm run verify:backup`       | PostgreSQL 17 archive, off-server copy, isolated semantic restore, failure paths, cleanup                                   | release summary |
| 4     | `npm run verify:ui`           | complete moderator journey                                                                                                  | release summary |
| 5     | `npm run verify:ui-hardening` | Chromium laptop, WebKit iPad, compact-tablet accessibility and layout checks                                                | release summary |
| 6     | `npm run verify:session`      | authenticated authoritative session create/save/reset/restore/reopen/cleanup                                                | release summary |
| 7     | `npm run verify:oauth`        | authenticated connected-account, playlist, playable-item, and UI-selection check                                            | release summary |

The exact SHA, date, target origin, gate durations, and final result belong in the issue #23 closeout comment. Cookies, account labels, tokens, playlist identifiers, player data, and query strings do not.

## Operational drill matrix

| Drill                        | Pass condition                                                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controlled migration failure | An unreachable migration database prevents application startup.                                                                                            |
| Repeat migration             | The one-shot migration converges successfully after the initial run.                                                                                       |
| Graceful termination         | The application handles `SIGTERM` and leaves PostgreSQL durable.                                                                                           |
| Active-game crash            | The Compose drill sends `SIGKILL` only after an authoritative day-phase game is durably readable.                                                          |
| Restart restore              | The restart policy brings the real app process back and the complete current-format authoritative session and accepted canonical events read back exactly. |
| Backup and off-server copy   | The custom archive is copied outside the database container and byte-verified.                                                                             |
| Isolated restore             | A separate PostgreSQL 17 target restores and passes semantic readback.                                                                                     |
| Cleanup                      | Verifier-owned sessions, players, containers, networks, volumes, images, and temporary credentials are removed or make the gate fail.                      |
| Rollback decision            | Application rollback and database recovery are evaluated separately; neither silently triggers the other.                                                  |

Operational details live in the [self-hosted deployment guide](../self-hosted-deployment.md), [Azure deployment guide](../azure-deployment.md), and [PostgreSQL backup and recovery runbook](../postgresql-backup-and-recovery.md).

## Supported deployment boundary

- Authenticated ten-seat Club Mafia moderation with strict club isolation.
- English and Russian club interfaces using the fixed supported ruleset.
- Approved landscape profiles: Chromium laptop, WebKit iPad, and compact Chromium tablet.
- PostgreSQL 17.
- Current schemas and data formats only; no historical browser/API/replay migration, schema upgrades, or previous-image compatibility promise. Existing environments must not be reset automatically.
- Self-hosted Docker Compose or the documented Azure single-region pilot configuration.
- Azure remains a 0–1 replica, non-HA pilot; horizontal scaling requires shared rate-limit and coordination state.
- Google authentication, YouTube Music, Google Fonts, container registry, and hosting-provider availability remain external dependencies.

## Security and privacy residual risks

The release inherits the accepted boundaries in [security and privacy](../security-and-privacy.md): in-process authentication limiting for 0–1 replica deployments, no centralized security audit ledger, operator access to infrastructure and backups, documented CSP compatibility allowances, and no infrastructure-level WAF guarantee. Release evidence must remain redacted and must never contain authentication cookies, OAuth credentials, private game events, account labels, playlist IDs, or player personal data.

## Explicit v1 exclusions

Export is not included in v1.0.0. There is no JSON or CSV export gate and no promise that export will be added later. Any future export design must preserve club isolation and prevent secret game events, OAuth material, logs, and non-consented personal data from leaking.

The supported baseline also excludes high availability, horizontal scaling, a self-hosted continuous-WAL/PITR guarantee, a centralized audit ledger, additional game formats, and automatic database rollback.

## Rollback

For Azure, redeploy the previous known-good immutable image digest as described in the [Azure rollback procedure](../azure-deployment.md#rollback). Do not assume rerunning an old commit recreates an artifact-identical image.

For self-hosting, restore the previous known-good image digest and configuration using the [self-hosted rollback procedure](../self-hosted-deployment.md#rollback). Application rollback does not reverse committed schema changes. If a migration is incompatible or destructive, stop the application and use the separately tested [database recovery procedure](../postgresql-backup-and-recovery.md); do not improvise manual down migrations or restore a database merely because an application revision failed.

## Qualification evidence

The durable evidence record is the final comment on [issue #23](https://github.com/zemskovmm/mafia-dashboard/issues/23). It must contain:

- the verified remote commit URL and full SHA;
- the expected root `package.json` major/minor plus `APP_BUILD_INDEX` and exact `/health/version` readback;
- UTC execution time and target origin, without query strings;
- all seven gate results and durations from the redacted `verify:release` summary;
- confirmation that verifier-owned resources were cleaned up;
- the deployed immutable image digest when available;
- links to this checklist and the rollback runbooks.

Screenshots and detailed logs may remain local; only non-sensitive paths, counts, and bounded diagnostics may be cited.

## Sign-off

Release sign-off occurs only when the exact pushed deployment passes `npm run verify:release`, the local and remote SHAs match, the evidence comment is read back successfully, and issue #23 is closed as completed. Until then this document remains a release contract, not a PASS declaration.
