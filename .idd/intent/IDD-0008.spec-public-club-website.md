# IDD-0008.spec-public-club-website

## Intent

Provide La Verdad's public Russian-language club website independently of the authenticated Mafia Dashboard. Preserve the existing club presentation and published articles while explaining and linking to the host application. The website is suitable for static hosting on GitHub Pages without a backend.

## Related Specifications

- IDD-0001 owns authenticated club access and private player/game information; the public website does not weaken that boundary.
- IDD-0003 owns the host application's presentation and controls, not the public website's content or navigation.

## Behavior

- The homepage preserves the club introduction, sporting-Mafia features, testimonials, learning resources, beginner checklist, night quotation and complete club rules in their existing Russian wording and order.
- The published game-analysis articles remain directly accessible at `/games/2026-08-17` and `/games/2026-09-06` beneath the configured site base. Their full prose, lists, emphasis and illustrations remain available without signing in or running client-side JavaScript.
- The site's La Verdad identity, original artwork, dark/gold styling and responsive composition remain recognizable and faithful at desktop, tablet and phone sizes. An openly licensed geometric display face replaces the source's Doloman Pavljenko font; the original font is not redistributed. Required asset/font notices and visible icon attribution are preserved. Content and controls do not clip or overlap on narrow screens.
- Existing section navigation, Telegram actions, tutorial/playlist links and Back to top remain usable. The main Vimeo video and short YouTube video retain their identities. Videos load only when requested; closing the short-video dialog stops its playback. A direct source link remains available when an embed cannot play or JavaScript is disabled.
- A compact homepage section explains the hosting app's actual capabilities and shows a privacy-safe image of its real interface. A clearly labelled action and shared footer link navigate to the separately hosted live application; they are not game-registration controls. Telegram remains the primary club-joining destination.
- Ordinary content, images, links and the app introduction are static. Keyboard navigation, meaningful headings/image alternatives and reduced-motion preferences are supported.

## Product-Significant Architecture And Constraints

- The public website requires no server application, database, authentication, server-side rendering or dashboard API. It can be published as static files on GitHub Pages, either beneath a repository path or at a custom-domain root.
- Local assets and internal navigation respect the configured site base. Article URLs resolve through ordinary static directory indexes, not a dashboard SPA fallback. Public metadata reflects the configured public origin and base, never a local development address.
- Owned images, permitted fonts and icons are served with the website, without Tilda runtime, tracking or asset dependencies. Intentional Telegram, video-provider and app links remain external.
- The website neither embeds the dashboard nor reads its session, player data, game records or secrets. Public app illustrations use synthetic/non-personal content; existing authorized public club content is distinct from private application data.
- Website publication is independent of the Azure app release. Its publication artifact contains only the static website, not server code, credentials, development fixtures or execution evidence. Publication is explicitly invoked, not triggered automatically by ordinary application pushes.

## Non-Goals

- A CMS, player portal, public spectator service, registration/payment backend or live app integration.
- Rewriting historic articles or club rules to mirror current game-engine behavior.
- Moving the hosting application to GitHub Pages or changing its authentication, persistence or deployment.

## Acceptance Criteria

1. The homepage and both complete articles are readable and directly navigable from a plain static host with JavaScript disabled.
2. All owned visual assets load locally and the original club content remains intact when Tilda domains are unavailable.
3. Source/replacement visual comparisons cover desktop, tablet and narrow-phone layouts, including all homepage sections and both article layouts.
4. Section links, external learning/Telegram actions, video opening/closing and the labelled app links behave as described. No public page requests the dashboard API.
5. Both repository-prefix and root-domain builds preserve asset URLs, direct article requests and correct canonical/sitemap metadata without a catch-all application server.
6. The app overview uses a genuine, privacy-safe UI image and accurate feature copy; it does not expose live club information or suggest registration occurs in the dashboard.
7. The static publication boundary excludes the protected application and local execution material, and website publication does not trigger or replace the Azure release.
